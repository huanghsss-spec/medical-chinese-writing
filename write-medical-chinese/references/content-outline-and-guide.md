## 内容型总纲的定义

把内容型总纲作为全文的压缩知识版本和写作控制中心。它既包含目录，也包含现有材料的精炼整合、统领性问题的回答、章节功能、读者路径、证据和团队基础分配、字数预算、来源及处理状态。

“覆盖全部信息”表示每项重要信息都有摘要、来源、归属和处理记录，不表示把所有原文复制进总纲。

传统目录只有标题时，先扩展为内容型总纲，再进入正式成稿。

## 大纲门控

对新项目、完整初稿、全文重构和指南约束下的章节写作，先索取可用材料。

Grant优先索取：

- 申报指南和版本；
- 标书模板、固定标题和填报说明；
- 各模块字数和计数口径；
- 评审维度或评分要求；
- 用户现有大纲；
- 前期基础、研究数据和文献材料。

Journal优先索取：

- 目标期刊或学位论文类型；
- 文章类型和投稿指南；
- 章节、摘要、图表、参考文献和字数要求；
- 用户现有大纲；
- 研究目的、方法、结果、图表和主要结论。

用户没有大纲时，基于交付物、指南、核心问题和现有材料主动建立。用户要求直接完成时，不展示中间确认也可以，但必须先在内部完成总纲。

完整标书、论文或重大重构默认在总纲形成后设置一次集中确认节点。向用户展示写作目的、中心命题、合规结构、科学结构、初步叙事路径、字数预算、关键证据、团队基础和待核实事项，不逐段反复确认。

集中确认通常优先锁定合规结构和科学结构。叙事结构应形成推荐方案，但只有章节功能、读者路径、信息顺序和论述力度已经验证后才标记为已锁定。输出结构可以依据官方模板独立锁定。

## 材料盘点与信息单元

盘点用户提供和项目目录中明确置于写作范围内的：

- 指南、模板和规范；
- 既有大纲和各版正文；
- 前期基础、实验结果和图表；
- 文献综述、证据表和参考文献；
- 审稿意见、专家意见和用户批注；
- 对话中已确认的写作决策；
- 字数、格式、保密和提交要求。

把材料拆分为独立信息单元，并区分：

- 事实；
- 外部证据；
- 团队前期结果；
- 作者解释；
- 科学假设；
- 研究计划；
- 预期结果；
- 限制、风险和待核实信息。

为每项重要信息记录：

| 字段 | 内容 |
|---|---|
| 信息编号 | 稳定标识 |
| 精炼摘要 | 保留医学含义的简要表述 |
| 来源 | 文件、文献、数据或用户决定 |
| 证据状态 | 已发表、未发表、初步观察、假设、计划等 |
| 归属章节 | 主要承载位置 |
| 论证功能 | 核心证据、边界、桥梁、团队基础等 |
| 处理状态 | 已纳入、备用、重复、冲突、待核实、暂不使用、迁移中 |
| 迁移方向 | 无、上提、下沉、后移、转移承载或保留下游 |
| 目标位置 | 迁移后的章节、节点、表格或内部控制文件 |
| 处理理由 | 删除、保留或降级的理由 |

合并重复信息。不同来源冲突时保留双方来源和冲突状态，不静默选择。

## 信息迁移

章节职责或抽象层级改变时，内容可以从当前位置移至更合适的承载位置。使用：

- **上提**：由局部发现或任务提升为中心命题、总体问题或上位判断；
- **下沉**：由总体表述移至分问题、研究内容、方法、终点或指标；
- **后移**：当前章节只保留必要入口，具体内容由后续章节展开；
- **转移承载**：从不合适的章节移至风险、组织实施、决策记录或其他明确位置；
- **保留下游**：上位文本不再明示，但相关意义单元仍必须由既定下游节点实现。

每次迁移记录原位置、目标位置、必须保留的意义单元和传播状态。只有目标位置已经实现，或明确登记为内部控制信息且不应进入正文，才关闭迁移。不得把真正遗漏标记为“后移”，也不得要求上位文本为证明一致性而重复全部下游细节。

## 统领性问题

在总纲最前面形成能够统领全文的压缩回答。

### Grant

回答：

1. 为什么需要研究；
2. 已经知道什么；
3. 具体缺少什么证据；
4. 核心科学问题是什么；
5. 科学假设是什么；
6. 准备通过哪些任务验证；
7. 团队为什么能够完成；
8. 相对既往工作的增量是什么；
9. 预期形成什么科学贡献和潜在价值。

### Journal

回答：

1. 研究回答什么问题；
2. 为什么需要开展；
3. 使用什么研究设计；
4. 主要结果是什么；
5. 结果支持什么结论；
6. 哪些解释仍受限制；
7. 相比既往研究增加什么；
8. 对后续研究或实践有什么意义。

若现有材料不足以回答，标记缺口，不根据常识补造事实、数据或结论。

## 科学问题层级

根据章节功能区分：

- **描述性问题**：对象在不同人群、阶段、空间或条件下呈现何种分布或变化；
- **关系性问题**：一个对象与另一个对象、过程或结局如何关联或相互影响；
- **机制性问题**：作用顺序、依赖性、必要性、介导过程或具体功能环节是什么；
- **转化性问题**：哪些可操作对象、分层因素或候选措施值得进入后续验证。

关键科学问题章节不应只是材料、指标或技术对象的并列清单。先确定总体问题的主要关系链，再判断每个分问题承担描述、关系、机制或转化中的哪一层。总体问题不必容纳全部下游终点；被移出的维度必须登记为下沉或保留下游，并能够映射至研究目标、内容、方法和终点。

不得为了“问题驱动”把所有描述性问题强行改成因果或机制问题。问题层级必须与研究设计、已有证据和实际测量能力相符。

## 指南要求矩阵

把指南原文作为最高优先级外部依据，保留来源、版本和条款原意。提取为操作矩阵：

| 要求编号 | 指南原始要求或准确摘要 | 类型 | 主承载章节 | 辅助章节 | 是否强制 | 完成状态 |
|---|---|---|---|---|---|---|

类型包括但不限于：

- 固定模块和标题；
- 内容要求；
- 字数和计数口径；
- 评审关注点；
- 图表、附件和格式；
- 禁止或限制内容；
- 资格、伦理、数据和开放要求。

给跨章节评审要求指定主承载章节和辅助章节，避免每章重复项目意义、创新性和团队优势。

指南不明确或不同文件版本冲突时，提示用户核实；不得猜测硬性字数或提交规则。

指南要求矩阵用于完整保留条款、豁免、计数口径、风险和内部判断；指南关联正文则只呈现评审需要的清楚结论。撰写匹配性或关联关系章节时，可以按“具体研究内容与要求逐项对应 → 项目整体对方向目标的支撑 → 考核指标或完成判定的落实”形成层次。具体项负责解释实际任务如何对应指南，总领项负责综合已有对应关系，不新增研究任务。该结构不固定为四点，点数由指南要求和项目内容决定。

只有官方表格明确要求，或省略后会影响合规判断时，才在正文解释类别豁免、周期、经费、团队配置或指标数量。其他内部合规推理保留在矩阵、决策记录或风险控制中，正文直接说明项目做什么、如何支撑指南以及以何种指标判定。使用“完全覆盖”“全部满足”等表述前，必须由矩阵逐项核对支持。

## 要求原子化与结构化子交付物

指南矩阵中的一行可以包含多个可独立验收的动作。继续把含有“并、同时、另附、另列、分别、包括、至少、不超过”等表达的条款拆成要求原子，分别登记正文、表格、图示、附件、系统字段、数量和排序要求：

| 原子编号 | 上位要求 | 动作 | 对象与范围 | 数量或边界 | 承载形式 | 与前文或前表关系 | 验收方法 | 状态 |
|---|---|---|---|---|---|---|---|---|

正文完成不自动关闭同一句中的表格或附件要求。对代表性成果、典型案例、机构比较和其他遴选型表格，先锁定领域整体、团队、负责人、合作单位或其他对象范围，再定义上游候选池、硬性准入和软性排序。若下游表从上游表遴选或汇总，逐行记录来源映射；若两表独立，明确记录独立关系，避免机械强制对应。

完整规则见 [structured-deliverables-and-table-lineage.md](structured-deliverables-and-table-lineage.md)。

## 内容型总纲结构

至少包含：

1. 项目定位和活动交付物；
2. 指南对齐说明；
3. 统领性问题和压缩回答；
4. 全文目录、章节功能、读者路径和字数；
5. 每个章节及其结构化子交付物的精炼内容；
6. 问题、目标、内容、方法、终点和创新性对应；
7. 全文一致性账本的路径、版本和核心节点摘要；
8. 团队基础与研究任务对应；
9. 预期成果和完成判定；
10. 信息覆盖表；
11. 证据冲突和待核实事项；
12. 决策来源和确认状态；
13. 四类结构状态和变更记录。

每个章节的精炼内容应是一至数段能够回答本节统领性问题的压缩原型，而不是关键词堆积。正式正文在该原型上展开。

总纲同时记录读者路径：读者进入本节前已经知道什么、本节需要形成什么新增判断、核心证据如何推进、段末留下什么问题供下一节回答。科学问题和章节顺序正确，不表示读者路径已经清楚。

## 章节任务书

为每个正式模块建立独立任务书。使用 `assets/SECTION_BRIEF.template.md`。

至少记录：

- 官方标题和原始要求；
- 本节写作目的；
- 本节唯一外部任务及不承担的任务；
- 句级要求原子、附属交付物、来源池、表间关系和验收方法；
- 读者阅读前已经知道什么；
- 评审者或读者需要形成的新增判断；
- 必须回答的问题；
- 必须具体呈现、可以概括和限制展开的内容；
- 核心判断和精炼回答；
- 核心证据、团队基础、引文范围和证据边界；
- 建议段落顺序、每段功能和真实逻辑桥梁；
- 必须保留的组织性说明，以及应迁入内部控制文件的防御性或过程性信息；
- 上一章节的落点和下一章节的进入点；
- 硬性上限、内部目标和段落预算；
- 需要由抽象判断改为具体过程的位置；
- 合规、科学、叙事和输出结构状态；
- 待核实事项和当前状态。

写作时区分章节职责。例如：

- 国内外现状说明已有认识、具体缺口、发展方向和项目入口，不展开完整实验步骤；
- 研究目标把科学问题转化为明确、可验证的目标，不复制背景；
- 研究内容说明每项任务具体回答什么，不写成技术名词清单；
- 方法与技术路线说明对象、比较、干预、检测、分析、终点、风险和替代方案，不重复大篇幅研究意义；
- 创新性说明相对增量及验证方式，不用“首次、领先”代替比较。

根据具体指南调整，不机械套用上述章节。

## 读者路径与内容配额

在章节任务书中先规划读者路径，再安排段落和句子：

> 读者进入点 → 当前问题 → 具体证据 → 综合解释或边界 → 未决问题 → 章节落点

根据章节功能分配：

- **必须具体呈现**：核心发现、主要数据、关键比较、直接团队基础和必要边界；
- **可以概括处理**：同类方法、重复文献、常识背景和低优先级技术细节；
- **限制或禁止展开**：抢占其他章节职责、未经核实、仅展示复杂度或不推进判断的材料。

任务书中的限制必须成为成稿验收条件。若限制展开的技术名称仍出现在正文，说明其不可替代的论证作用；无法说明时删除或概括。

专业可读性计划至少识别：复杂概念的解释位置、抽象名词堆叠、容易省略的中间过程、谨慎措辞集中位置和可以直接陈述的研究行动。

## 跨章节对应

为Grant建立：

> 指南G → 中心命题P → 科学问题Q → 科学假设H → 研究目标O → 研究内容C → 方法M → 技术路线T → 终点E → 考核指标K → 预期结果R → 创新点I → 团队基础B → 风险与替代方案A

检查：

- 每个目标是否有内容和方法；
- 每项方法是否服务于明确目标；
- 每项预期结果是否有评价指标；
- 创新点是否来自实际研究增量；
- 研究现状提出的缺口是否被后文回应；
- 团队基础是否支持相应任务；
- 风险和替代方案是否覆盖关键不确定性。

内容型总纲保留这条对应链的压缩版本；完整节点、必须继承的意义单元、允许变体、章节实现和传播状态写入 `CONSISTENCY_LEDGER.md`。总纲负责确定全文写什么，一致性账本负责追踪同一内容在各章如何提出、展开、验证和验收。详细规则见 [longitudinal-consistency.md](longitudinal-consistency.md)。

为Journal根据体裁建立对应关系，例如：

> 研究问题 → 设计与分析 → 结果 → 图表 → 讨论解释 → 局限 → 结论

不要强制非原始研究采用IMRaD。

## 字数预算

为每个模块记录：

- 官方硬性上限；
- 内部目标；
- 标题、标点、表格、图题和参考文献是否计入；
- 子章节和段落预算；
- 修改余量。

内部目标通常低于硬性上限，但余量比例根据提交系统和任务风险决定，不设固定通用比例。

压缩时先锁定章节任务和核心证据，再删除重复背景、同类文献、空泛意义和低优先级技术细节。保留具体发现、证据边界、团队基础和必要逻辑桥梁。

## 四类结构锁定

分别管理：

| 结构层 | 主要内容 | 常见锁定依据 |
|---|---|---|
| 合规结构 | 官方模块、标题、字数、表格和提交要求 | 官方指南或模板 |
| 科学结构 | 问题、假设、目标、内容、方法、终点和创新对应 | 用户确认及可靠项目材料 |
| 叙事结构 | 读者路径、章节职责、段落功能、证据顺序和节奏 | 章节任务书、成稿审计和用户反馈 |
| 输出结构 | 页面、字体、图表、引文和文件格式 | 官方模板或用户确认 |

每类使用“拟定中、待确认、已锁定、需重审”。记录已锁定内容、仍可调整内容和确认来源。

不得因为科学结构已经锁定而拒绝优化叙事结构，也不得以改善叙事为由静默改变核心科学问题。用户对可读性、过渡或节奏提出意见时，默认重审叙事结构；只有意见涉及研究任务、证据或结论时才扩大重审范围。

## 确认与更新

总纲整体可以记录“拟定中、待确认、内容更新中或需要重新审计”，但锁定状态必须按四类结构分别记录。

锁定后允许补充新证据。新增信息仅补强既有节点时，不重新询问；改变指南版本、核心问题、目标、章节职责、读者路径或输出要求时，只重审受影响的结构层，并检查其对其他层的连带影响。

后续章节或定稿使上位命题更准确时，先在一致性账本中区分受控细化、规范变体、上位命题校正和新增/废止节点。只有经确认的上位命题变化才回写内容型总纲，并同步标记所有受影响章节；不得让总纲长期停留在早于定稿正文的旧版本。

确认来源区分官方要求、用户明确确认、材料直接事实、系统推定、系统推荐和待外部核实。用户授权系统拟定方案不等于确认方案；未明确接受时保留为“系统推荐｜待确认”。

写作完成后检查信息覆盖表和章节验收表。正文可以因篇幅删除材料，但不得无记录地从总纲中消失。
