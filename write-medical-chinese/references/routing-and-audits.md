## 路由原则

先读取项目主控索引、活动交付物、四类结构状态和当前章节任务书。持续项目还必须读取全文一致性账本中与当前章节有关的上游、当前和直接下游节点切片。正式成稿前锁定本节唯一外部任务、不承担的任务、必要组织说明和最终落点，再根据用户目标、材料状态和修改范围选择最小但足够的处理层级。所有撰写、改写和审计任务使用内置叙事质量基线；日常运行不索要优秀范本。

不要因为用户使用“润色”一词就忽略明显的全文结构问题，也不要因为发现结构问题就擅自重写用户要求保持的结构。

识别三个输入状态：

- **无初稿**：指南、材料、数据、文献或要点已经提供，但正文尚未形成；
- **局部初稿**：已有章节、段落、表格或零散内容；
- **完整初稿**：已有全文，需要重构、压缩、润色或审计。

识别三个处理层级：全文建构、局部构篇和语言精修。结构审计与语言审计是质量门，不作为第四种写作层级。

## 全文建构

以下意图通常触发全文建构：

- 根据指南或材料撰写完整标书、论文或研究方案；
- 从零开始、设计全文框架或形成初稿；
- 重构全文主线、章节顺序或证据分配；
- 整篇压缩且需要重新分配篇幅；
- 从 Grant 改写为 Journal，或反向转换；
- 现有全文的核心问题、目标和章节功能不一致。

全文建构输出可以是内容型总纲、全文一致性账本、完整初稿或相应组合。分别记录合规结构、科学结构、叙事结构和输出结构状态。若用户需要正文，默认继续局部构篇和语言精修。

重大全文写作默认在内容型总纲形成后设置一次用户确认点；用户明确要求直接完成时可连续执行。

## 局部构篇

以下意图通常触发局部构篇：

- 撰写立项依据、国内外现状、研究目标、讨论等单独章节；
- 把要点、证据或文献写成连续段落；
- 调整章节或段落逻辑、顺序、过渡和信息权重；
- 合并重复材料、处理逐篇文献罗列；
- 压缩或扩写局部内容；
- 在既定全文结构中补写缺失段落。

局部构篇先读取相关一致性节点，形成“必须继承、允许细化、不得改变、向后传递”的章节继承契约；再锁定章节外部任务和禁止任务，区分必要组织说明与防御性、结构性或过程性元叙述；随后规划读者路径，并把材料分为必须具体呈现、可以概括、限制展开和迁移承载。默认继续语言精修。只要求结构方案时，可以停在章节任务书、段落角色图或重构提纲。

## 语言精修

以下意图通常只触发语言精修：

- 明确要求保持结构、数据和引文不变；
- 统一医学术语、缩写、单位和标点；
- 修改病句、冗余和不规范表达；
- 调整 Grant 或 Journal 语域；
- 提交前进行语言层面校对。

语言精修仍需读取写作目的、章节功能、相关一致性节点和内置叙事质量基线。允许在段内调整普通句序、合并同义表达、把抽象判断改为不增加事实的具体过程表达，以及添加必要承接句；不得以同义改写为名改变精确锚点、语义锚点、重要证据、章节顺序或核心主张。词语调整一旦造成范围扩大、范围缩小、对象替换、关系改变或证据身份改变，即退出纯语言精修并进入相应结构审计。

## 联合调用

常见自动路由：

| 用户目标 | 默认调用 |
|---|---|
| 根据材料写完整标书或论文 | 全文建构 → 局部构篇 → 语言精修 |
| 建立内容型总纲或全文框架 | 全文建构 |
| 撰写或重构一个章节 | 局部构篇 → 语言精修 |
| 撰写任务分解、研究组关系或概念性结构图 | 局部构篇 → 四层任务映射与图示语义契约 → 语言精修 |
| 调整段落逻辑和过渡 | 局部构篇 → 语言精修 |
| 只修改措辞，不动结构 | 语言精修 |
| 全文压缩到硬性字数 | 结构审计 → 全文建构或局部构篇 → 语言精修 |
| 润色完整标书或论文 | 先做结构与语言快速审计，再选择必要层级 |
| 检查问题，不要求修改 | 相应审计，不生成改稿或只给示例 |

若用户任务已经明确授权“重构、整体优化、限字重写”，不重复询问结构调整权限。

## 修改权限

按用户动词设置边界：

- **撰写**：基于用户材料和已获授权的可靠来源生成内容；区分事实、假设、计划和预期。
- **全文建构或重构**：允许调整章节、信息位置和篇幅；保护事实、数据、证据状态和指南要求。
- **局部构篇或改写**：允许重组当前章节和段落；不擅自改变全文目标。
- **压缩**：允许删除低优先级内容；保留核心具体证据、否定、不确定性、主要结果和必要局限。
- **扩写**：补充材料中已经存在的解释和逻辑；不生成无来源事实、数据或文献。
- **语言润色**：保持结构和主张，仅进行必要的局部句序与衔接调整。
- **审校或审计**：识别问题并按用户要求提供修改建议；不把诊断自动扩大为全面重写。
- **事实核查**：基于可靠来源核实主张；区分原文、核实结果和修改建议。

用户未说明时，采用“允许改善局部结构和语言，但锁定医学主张、重要证据和引用范围”的保守权限。

## 四类结构状态

路由前分别判断：

- **合规结构**：官方模块、标题、字数、表格和提交要求；
- **科学结构**：问题、假设、目标、内容、方法、终点和结论对应；
- **叙事结构**：读者路径、章节职责、段落功能、证据顺序和节奏；
- **输出结构**：页面、字体、图表、引文和文件格式。

每类使用“拟定中、待确认、已锁定、需重审”。科学结构已锁定但读者理解困难时，只重审叙事结构；用户要求更换研究目标时，不得把它当作普通叙事调整。

## 用户介入节点

仅在决定会实质改变交付物时要求用户介入。

### 1. 项目首次建立

当模式、活动交付物、指南版本或多个模板存在实质歧义时，让用户选择。没有指南或大纲时，先给出推荐方案，不要求用户自行从零编写。

### 2. 内容型总纲锁定

完整标书、论文或重大重构时，集中请用户确认：

- 写作目的和中心命题；
- 核心问题或主要结论；
- 章节结构和功能；
- 目标、内容和方法对应；
- 精确锚点、语义锚点和主要跨章节对应链；
- 字数预算；
- 关键证据、团队基础和待核实事项。

同时展示四类结构状态、确认来源和系统推荐项。通常优先锁定合规结构与科学结构；叙事结构可以在首轮成稿和审计后继续优化。提供“确认并继续（推荐）”“修改结构”“先补充材料”等少量选项。

### 3. 事实或证据冲突

样本量、结果、成果归属、前期状态、合作单位或指南要求冲突时，说明来源、影响和推荐。无法确认的内容标记待核实，不写成确定事实；继续处理不受影响的部分。

### 4. 权限升级

用户要求语言润色，但需要重大重构、删除重要文献、改变引用范围或重新分配核心证据时，提供：

1. 全文建构＋局部构篇＋语言精修（推荐）；
2. 局部构篇＋语言精修；
3. 仅语言精修，保持结构。

### 5. 最终提交

形成提交版或投稿版前，集中确认未发表数据、敏感内容、合作归属、字数口径、待补图表、统计信息和过强结论。普通初稿不设置这一门槛。

术语统一、常规句序、必要过渡、重复压缩、字数统计、材料映射和审计自动执行，不反复询问。

不把优秀范本作为日常用户介入节点。只有用户明确要求用范本改进 Skill 时，才进入范本经验提炼流程。

用户明确要求比较人工修订稿、吸收反馈或校准 Skill 时，也进入 [exemplar-learning.md](exemplar-learning.md) 的人工修订流程。先核验版本和内容完整性，不把缺失内容直接解释为有意删除。

## 结构审计

结构审计先区分四个子层，再覆盖章节和全文两个尺度。

### 合规审计

检查官方模块、固定标题、内容要求、字数和计数口径、表格、附件、伦理及提交限制是否完成映射。

标题、段落或表格单元未出现时，先列为“缺失候选”，核对提取结果、模板结构和用户反馈后再判断是硬错误、意外遗漏、特意留空或有意删除。

### 科学架构审计

检查研究问题、假设、目标、内容、方法、终点、结果、创新、风险和团队基础是否对应；新增材料是否改变事实、证据边界或任务范围。

### 叙事架构审计

检查读者路径、章节职责、段落功能、证据位置、信息权重、抽象—具体关系、逻辑桥梁、论述力度和章节落点。科学结构正确但读者仍需自行补足中间过程时，判为叙事问题。

### 纵向一致性审计

按稳定节点检查同一科学命题从总纲到章节、表格、图示和附件的继承、细化与验收：

- 精确锚点的名称、编号、数字、终点、指标和证据身份是否一致；
- 语义锚点是否保持主体、关系、方向、条件和边界；
- 方法、技术路线和分析是否归属于既有目标与内容；
- 上游承诺是否具有下游实现和验收方式；
- 下游新增内容是否形成未经确认的孤立任务；
- 后续定稿的实质变化是否完成反向校准和传播；
- 一致性是否通过章节功能递进实现，而非机械重复相同句子。

详细流程见 [longitudinal-consistency.md](longitudinal-consistency.md)。

### 章节结构审计

检查：

- 是否完成章节任务书规定的功能；
- 是否回答统领性问题；
- 是否满足指南和字数要求；
- 核心证据是否具体并位于合适位置；
- 团队基础是否回应相应缺口；
- 是否存在文献罗列、信息错位或段落跳跃；
- 结尾是否完成章节落点；
- 是否抢占其他章节内容；
- 必须具体呈现、可以概括和限制展开的内容是否按任务书执行；
- 是否先说明问题，再引入方法和技术名称；
- 是否完成本节唯一外部任务，且未以防御性解释、章节结构自述或过程自述替代科学论证；
- 必要组织说明是否位于真正承担该功能的章节，迁移内容是否具有明确目标位置；
- 是否完整继承本节相关节点，且新增细节没有改变上游任务身份；
- 任务分解是否区分官方组织任务、科学内容模块、研究阶段和图示节点，并把任务职责与直接关系一体化呈现；
- 概念图是否具有唯一外部任务，每种箭头是否只表达一种关系，实际渲染方向和图文一致性是否通过核验；
- 是否记录需要向后续章节传播的终点、指标、边界或规范变体；
- 读者能否在不了解历史对话时理解本节推进。

### 全文结构审计

检查：

- 写作目的、中心命题和目标读者是否一致；
- 指南要求是否全部映射；
- 章节顺序、功能和字数是否合理；
- 科学问题、目标、内容、方法、终点、结果和创新性是否对应；
- 术语、研究对象、时间点和终点是否跨章节一致；
- 信息是否重复、遗漏、提前或错位；
- 团队基础和预期贡献是否与研究任务匹配；
- 新增材料是否造成结构漂移。
- 每个上游承诺是否具有下游内容、方法、终点和验收方式；
- 每个方法、指标和创新点是否具有上游来源；
- 摘要、正文、表格、图示和附件是否使用同一权威节点版本；
- 后续定稿是否已经反向校准总纲和所有受影响章节；
- 是否存在缺失、孤立、越界、重复或已经废止的节点。

结构审计可输出：四类结构状态、当前结构图、一致性节点状态、主要断点、严重程度、推荐结构、需要调用的写作层级、待传播项目和待确认事项。

## 语言审计

语言审计覆盖三个子层。

### 医学与证据表达

检查：

- 医学术语、缩写、名称和单位；
- 证据强度、因果关系和适用范围；
- 数据、方向、时间点和参照组；
- Grant 或 Journal 语域；
- 商业化、互联网化、宣传性和口号式表达；
- 句子完整性、歧义、重复和修饰语堆叠；
- 双引号、连接词、标点和格式；
- 阳性/阴性标记、离子电荷、价态、自由基、同位素、化学式原子数和基因型的上下标语义；
- 修改是否改变事实、引文和医学含义。

### 专业可读性

检查：

- 抽象判断是否具有具体对象、动作、方向和条件；
- 是否存在连续名词堆叠但缺少生物学或临床过程；
- 主语、比较对象、时间和参照方向是否清楚；
- 复杂概念是否先说明与当前问题的关系；
- 谨慎措辞是否准确但不过度分散；
- 技术名词是否具有不可替代的论证作用。

### 表层语言

检查Grant或Journal语域、商业化和互联网化表达、口号句、病句、重复、连接词、双引号、标点、单位和格式。正式编号分级标题默认各级加粗，正文编号列举不自动加粗。生物医学符号按完整语义决定上标、下标或基线，并检查字符边界、后续空格和富文本可检索性；不得把阴性标记与连字符、范围或负号混淆。模板复选框、内容控件和显示性标记属于输出控件，以最终可见状态和官方要求为验收依据；不得因纯文本提取出现占位字符就自动判为正文符号错误。上位模板要求优先。

证据在两类审计中的功能不同：

- 结构审计判断证据是否必要、放置合理并承担清楚任务；
- 语言审计判断证据是否被准确表达并具有适当强度。

## 输出方式

撰写、改写、压缩和润色默认输出完成稿，不复述内部流程。

用户要求审计时，按需要输出：

1. 结论和严重程度；
2. 主要问题及影响；
3. 推荐结构或修改原则；
4. 修改稿或示例；
5. 需用户确认和需核实事项。

不要把偏好差异列为事实错误。只有问题影响医学事实、证据、因果、指南合规、核心结构或最终提交时，列为实质性问题。

## 人工修订比较

比较系统稿与人工稿时，按顺序执行：来源身份与摘要核验 → 内容完整性门控 → 编辑残留门控 → 差异提取 → 用户理由核对 → 修订维度分类 → 作用域与行动状态登记 → 泛化候选测试。用户指定终版时，在该指令之后重新读取并计算最新摘要；不得用此前核验值直接锁定。

修订维度分为：内容完整性、抽象度或具体度、科学范围与任务边界、证据或主张强度、语言与专业可读性、输出格式。涉及科学范围或任务边界时，再标记语义方向：范围扩大、范围缩小、对象替换、关系改变、证据身份改变、层级迁移或纯语言调整。审计结论再区分：

- **硬错误**：违反官方要求、事实、证据或语法；
- **编辑残留**：输入错误、移动后重复、复制遗漏、概念赘词、无功能空段或继承格式，不能据此推断用户偏好；
- **缺失候选**：尚未确认是有意删除还是意外遗漏；
- **项目风险**：可能造成纵向不一致或提交风险；
- **局部偏好**：当前语境的可接受选择，不自动全局化；
- **模板提取伪影**：文本提取异常但最终视觉控件可以正确显示。

用户表示当前不处理时，记录为“仅当前交付物暂不处理”，不要把问题关闭为“已证明正确”。用户明确留空时记录字段、交付物和重新开启条件，避免后续自动填充。
