## 定位

纵向一致性是指同一科学命题在总纲、摘要、科学问题、目标、研究内容、方法、技术路线、终点、考核指标、创新性、研究基础和风险方案中保持对象、关系、方向、证据边界和任务身份一致，同时根据章节职责逐步增加细节。

一致性不等于复制。前文负责提出和压缩，后文负责分解、验证、测量和验收。后文可以改变句式、信息密度和展开层级，但不得静默更换研究对象、把候选关系写成既定机制、增加未被上位结构承诺的独立任务，或让同一指标在不同章节出现不同数量、条件和终点。

## 一致性的三个层级

### 精确锚点

以下内容原则上保持完全一致或只使用已经登记的规范变体：

- 官方项目名称、指南条款和固定模块；
- 研究对象、人群、组织、疾病阶段和任务编号；
- 已锁定的专名、缩写、机制名称和研究组名称；
- 样本量、任务数量、时间、剂量、终点、指标值和成果数量；
- 已确认的证据状态、成果归属和禁止性边界。

精确锚点发生变化时，不以“语言优化”处理。先核对来源和作用域，再判断是否需要用户确认及跨章节传播。

### 语义锚点

科学问题、科学假设、研究目标、关键作用关系和预期贡献允许根据章节功能改写，但必须保持：

- 主体和客体一致；
- 作用方向和关系类型一致；
- 已知、初步观察、假设、计划和预期的证据身份一致；
- 适用条件、疾病阶段和外推边界一致；
- 与上游问题和下游验证任务的对应关系一致。

语义锚点不要求全文重复同一句话。记录“必须保留的意义单元”和“允许变体”，而不是锁死整句表面形式。

### 递进细化

研究方法、技术路线、实验步骤、数据分析、质量控制和替代方案可以在后文展开。新增细节必须：

1. 归属于既有科学问题、目标或研究内容节点；
2. 说明其解决的问题、测量的终点或控制的风险；
3. 不把方法工具升级为新的独立研究目标；
4. 不扩大前文承诺或改变既有任务边界；
5. 与字数、可行性、团队基础和考核指标相匹配。

无法归属既有节点的新增内容视为潜在结构漂移，不自动纳入正文。

## 语义方向与信息迁移

重要改写除判断锁定层级外，还要标记其语义方向：范围扩大、范围缩小、对象替换、关系改变、证据身份改变、层级迁移或纯语言调整。前五类可能改变科学结构或证据边界，不能以语言润色权限静默完成；层级迁移必须记录原承载位置、目标位置和必须保留的意义单元。

上位问题、目标或总领句为突出主要关系链而省略某个维度时，将其登记为下沉、后移或保留下游。只要既定下游节点仍承担该维度且上位命题没有否定它，就属于受控迁移；若目标位置没有实现，则属于遗漏或未完成传播。

## 稳定节点与对应链

为持续项目建立稳定节点编号。Grant可使用：

> 指南G → 中心命题P → 科学问题Q → 科学假设H → 研究目标O → 研究内容C → 方法M → 技术路线T → 终点E → 考核指标K → 预期结果R → 创新I → 团队基础B → 风险与替代方案A

Journal可根据体裁使用：

> 研究问题Q → 假设H → 设计D → 方法M → 结果R → 图表F → 讨论解释X → 局限L → 结论C

节点字母仅用于稳定引用，不要求出现在正式正文。一个上游节点可以对应多个下游节点，但每个下游节点都必须具有可追溯的上游来源。方法、指标和创新不得成为没有问题或目标来源的孤立节点。

## 全文一致性账本

持续性标书、论文和多章节研究方案建立 `CONSISTENCY_LEDGER.md`，使用 [CONSISTENCY_LEDGER.template.md](../assets/CONSISTENCY_LEDGER.template.md)。账本记录：

- 节点编号、上游节点和当前权威命题；
- 锁定层级、必须继承的意义单元和允许变体；
- 禁止漂移的方向、边界、数字和证据身份；
- 首次承载章节、主要展开章节和下游使用章节；
- 当前权威来源、版本、确认状态和最后核对日期；
- 章节实现状态、冲突、变更及传播状态。

账本是总纲与正式章节之间的追踪层，不替代 `CONTENT_OUTLINE.md`、`PROJECT_FACTS.md`、`EVIDENCE_LEDGER.md` 或 `DECISION_LOG.md`：

- 内容型总纲回答全文写什么以及各章承担什么功能；
- 一致性账本回答同一节点在各章如何继承、细化和验收；
- 项目事实保存不随文体变化的事实和证据边界；
- 证据账本保存主张与来源、引文的对应；
- 决策记录保存决定的来源、作用域和状态。

## 术语一致性层级

术语一致不等于全文只允许一个表面词形。按科学身份和歧义风险分为：

1. **唯一规范词**：对象、终点、组别、任务编号或机制身份需要唯一写法；其他写法可能造成误解；
2. **受控同义词组**：两个或多个规范表达指向同一受控范围，可按章节和句法语境选择；
3. **语境优选词**：不同词语各有更合适的局部语境，不建立全局优劣关系；
4. **一次性表述**：只服务当前句、字段、标题或模板，不向全文传播。

受控同义词组也可以表现为“同一上位范围内的受控等价变体”：它们并非在每个具体语境都完全同义，但可在记录的上下文中分别选择。账本要记录共同上位指向、各自适用语境和不能替换的例外。不要为了“统一”在每处机械写成“甲/乙”；只有首次界定确有必要，或两个术语代表不同操作层级时才并列说明。局部人工采用某个词，只证明该处写法被接受，不自动把同组其他词列为错误。

上位语义锚点可以概括，下游节点可以递进细化。判断一致性时比较意义覆盖，而不是要求总体目标重复所有比较、验证链和技术步骤。只要下游仍归属于上位对象、关系和任务范围，就登记为受控细化或层级校正；下游失去上游来源时才判为漂移。

## 章节继承契约

每份章节任务书增加四类字段：

1. **必须继承**：上游已经锁定的精确或语义锚点；
2. **允许细化**：本节可以新增的方法、过程、比较、终点和解释；
3. **不得改变**：对象、关系、证据身份、数量、任务边界和已定稿内容；
4. **向后传递**：本节形成后必须由后续章节继续承接的节点、指标或风险。

章节任务书只复制当前任务需要的账本切片，并保留节点编号和账本版本。不得为了节省上下文而失去节点来源，也不要把全文账本完整复制进每份任务书。

## 写作前与写作后流程

### 写作前

1. 读取主控索引，确认活动交付物，并核验与当前任务有关的权威来源身份、版本和内容摘要值；
2. 读取当前章节任务书；
3. 读取一致性账本中本节涉及的上游、当前及直接下游节点；
4. 列出必须继承、允许细化、不得改变和向后传递的内容；
5. 检查当前正文或模板是否已有与账本冲突的表述；
6. 再进入局部构篇或语言精修。

即使用户只要求撰写或润色一个局部章节，也执行该最小一致性读取。无需加载全部历史版本和无关文献。

### 写作后

1. 检查所有必须继承节点是否出现并承担正确功能；
2. 检查新增细节是否能够归属既有节点；
3. 比较对象、方向、证据身份、数字、终点和任务边界；
4. 记录本节新增的受控细化，不自动提升为上位目标；
5. 识别需要向后续章节传播的表述、指标和风险；
6. 标记重要改写的语义方向和信息迁移去向；
7. 更新章节实现状态和最后核对日期；
8. 仅在已有授权且来源明确时回写控制文件，并建立传播目标清单。

## 反向校准与变更传播

后续章节可能使上位表述更准确。按影响分为：

在分类前先完成来源重新锁定。同一路径摘要值已经改变时，旧版本标记为“已被新版本替代”，重新提取锚点并执行完整性核对。缺少标题、字段或段落先记为“缺失候选”，不得直接推断为有意删除。

### 受控细化

只增加方法、比较、终点或解释，不改变上位命题。更新一致性账本和章节任务书，不要求重写总纲。

### 规范变体

改变句式或压缩方式，但保持语义锚点。登记为允许变体，避免后续把表面不同误判为矛盾。

### 上位命题校正

改变科学问题、假设、目标、研究内容、主要终点、指标或证据边界。先标记受影响节点和章节，说明旧表述、新表述及影响，取得用户确认后再更新上位总纲并向下游传播。

### 新增或废止节点

新增独立任务、删除既有承诺或改变研究组边界属于科学结构变更。不得在方法章节、表格或润色过程中静默完成。

传播顺序为：核验并重新锁定权威来源 → 更新节点 → 标记受影响章节 → 逐章核对 → 更新实现状态 → 完成全链条审计。来源重新锁定只确认当前应读取哪个版本，不自动授予修改既有控制文件或已确认章节的权限。已经由用户确认的定稿文件只登记冲突和建议，不未经授权修改。

### 传播闭环验收

变更记录只说明发生了什么，不证明当前系统已经采用新决定。每项需要传播的变更建立目标清单，至少核对：

1. 当前权威节点和允许变体；
2. 内容型总纲中的中心命题、科学问题或章节原型；
3. 当前章节任务书与继承切片使用的账本版本；
4. 受影响的活动正文、表格、图示或附件；
5. 主控索引中的活动状态、路径、版本和内容摘要；
6. 直接下游章节的待继承或待实现状态。

只有所有目标均已更新、明确登记为无需修改，或因定稿锁定而登记冲突并等待授权时，才能判定传播状态。存在任何未更新活动字段时保持“待传播”或“传播中”；仅追加变更行、备注、核对记录或“已更新”说明，不得标记为“已完成”。关闭前重新读取活动字段，不依赖变更记录自证完成。

## 一致性审计

把纵向一致性审计作为结构审计的独立子层。

### 增量审计

每完成或修改一个章节检查：

- **覆盖**：本节必须继承的节点是否出现；
- **身份**：同一对象、任务和指标是否保持稳定名称与编号；
- **关系**：作用方向、因果或相关边界是否一致；
- **证据**：前期观察、假设、计划和预期是否发生身份升级；
- **数字**：数量、时间、样本、终点和成果是否一致；
- **细化**：新增方法是否服务于既有节点；
- **漂移**：是否出现未被总纲承诺的新任务；
- **传递**：本节新增的受控细节是否需要后文承接；
- **重复**：一致性是否通过功能递进实现，而非机械复制。
- **迁移**：被上提、下沉、后移或转移承载的信息是否已经到达目标位置；
- **闭环**：变更是否更新活动权威字段，而非只存在于变更日志。

### 全文审计

提交前按节点而不是按文件顺序检查：

1. 每个上游承诺是否有下游实现和验收方式；
2. 每个方法、终点、指标和创新是否有上游来源；
3. 同一节点在摘要、正文、表格、图示和附件中是否一致；
4. 已定稿章节与后续细化是否存在未处理冲突；
5. 上位总纲是否已经吸收所有经确认的实质变化；
6. 是否存在缺失、孤立、重复、越界或已废止节点残留。

审计输出使用：一致｜受控变体｜层级迁移｜待传播｜传播中｜冲突｜待确认｜已被新版本替代｜已废止。只有通过传播闭环验收后才使用“传播完成”。

## 用户介入边界

以下情况需要用户确认：

- 改变精确锚点或语义锚点的科学含义；
- 新增或删除独立目标、任务、终点、指标或创新点；
- 不同定稿、官方材料或用户决定互相冲突；
- 反向校准会要求修改已经确认的定稿文件；
- 变化会影响任务分工、周期、预算、伦理或成果承诺。

普通句式变体、已授权的受控细化、节点位置调整和一致性状态更新默认自动完成，不反复要求确认。

## 旧项目迁移与上下文控制

旧项目已有单文件主控文档时，不要求立即拆分所有模块。先从已确认总纲和定稿文件提取：

1. 精确锚点；
2. 核心语义锚点；
3. 问题到指标的主要对应链；
4. 已知冲突和待核实事项；
5. 当前章节实现状态。

建立最小可用账本后，从当前章节开始执行增量维护。总纲、主控和定稿版本不一致时，以权威来源优先级判断；无法判断时记录冲突，不静默覆盖。

为控制上下文，每次只加载主控摘要、当前章节任务书和相关节点切片。完整账本用于全文审计、重大变更和版本迁移。
